2. 共通部品

shared/pdf-incr.js（増分更新エンジン）

  • nodo/nodo_core.js の読み取り・追記部分（Parser / Doc / Writer / rebuildDict / boxOf / pageGeom など）を1行も変えずに切り出したもの。EQUIOS を通った実績のあるコード。
  • 直すときは nodo_core.js と揃えること。末尾の「追加分」（deflate・startsWith）だけがこのファイル独自。

shared/edge-core.js（辺の判定と補正）

UI に依存しない処理だけを置く。主な関数： - readPages(buf)：ページとボックス。補正済みなら base（補正前のファイル長）も返す - sideRoles(pageIndex, opts)：天・地・小口・ノドの割り当て - analyzeEdges(imageData, geom, opts)：辺ごとの実測と、足りない区間（segments）。区間には補正用の edge（元の絵柄の端の折れ線）と axis（反転の軸。斜めなら傾き付き）も入る - refineEdges(edges, side, imageData, geom)：不足の辺の帯（stripRect() の範囲）を高い解像度で描いた画像から、edge・axis だけを測り直す（判定は変えない） - fillEdges(buf, jobs, opts)：補う（増分更新） - revert(buf)：補正前に戻す（追記部分の切り捨て） - expandCropForView(buf, pages)：表示専用。CropBox を MediaBox に広げた複製（保存には使わない） - toBleedGaps(pages)：dtp-preflight の BLEED_GAP 形式で書き出す

3. 断ち代チェック：判定

辺の割り当て

  • 右綴じ：奇数ページは小口が左、偶数ページは小口が右
  • 左綴じ：奇数ページは小口が右、偶数ページは小口が左
  • 「ペラもの・表紙」は4辺すべて対象。本文はノド側を判定しない
  • 抜き出しPDFのために「先頭ページのノンブル」を詳細設定に置いた

実測（200dpi でレンダリングし、列ごとに測る）

項目 値 理由
白とみなす濃さ 0%だけ（RGBの差 2/255 以下） 写真のハイライトは5%前後でも色が入っている。4%基準だと色変換やJPEGの揺らぎで白と判定され誤検知した（p.97 の件）
内側の確認位置 仕上がり線の 0.4mm 内側（3px平均） ここが白なら「仕上がり際が白＝補う必要なし」
網点の隙間 0.3mm 以下の白は絵柄が続いているとみなす。両隣の列も見る 網点・写真の明るい部分は点の間に白がある。網点があれば断ち代と判断してよい（中田さん確認）
許容誤差 0.2mm
短い区間 5mm 未満は前後に吸収 5月の preflight.py の MIN_RUN_MM=5 に合わせた。写真の中の小さな白で細かく割らない
段差 0.5mm 以上違えば別の区間 「上の写真は0.5mm不足・下の地色は2mm不足」のようなちぐはぐな形に対応
段差で分ける最小の長さ 5mm
写真のハイライト 前後が足りている・15mm以下・内側の平均が10%未満 → 写真の一部とみなして不足にしない 「写真の一部であれば良い」（中田さん）。詳細設定で外せる

部分的な不足

  • 足りている区間には一切触らない。例：p.15 の小口は上半分が写真（足りている）、下半分が地色（0mm）→ 下半分だけ補う
  • 「足りている」区間との境目は 2px 広げる（測るときに両隣の列も見ているので、境目に髪の毛ほどの白が残るのを防ぐ）。広げた所は元の絵柄が仕上がり近くまであるので、元の端から描けば重ならない
  • 「足りない」区間どうしの境目は広げない（ぴったり接する）。広げるとその幅が二重に描かれ、透明効果で濃くなる（2026-10-07）

4. 断ち代チェック：補正

  • 足りない分だけを補う。今ある断ち代は残す。最初は仕上がり線から3mm全部を描き直していたが「それはダメ」と指摘された
  • 区間ごとに、今ある絵柄の端を軸にする。軸は実際の端より 1画素＋0.05mm 内側（軸が端より外に出ると、そこが白く折り返されるため）
  • 反転：軸で折り返してコピー。引き伸ばし：軸のすぐ内側 0.1mm を外へ伸ばす。式は x' = c(1+k) − k·x（反転は k=1）

元の絵柄と重ねない（2026-10-07 p.86 の件）

  • 以前は反転コピーを軸から断ち代の外端まで描いていた。軸は端より内側なので、元の塗り足しの上に 0.03〜0.2mm 重なる（段差の区間では最大 0.5mm 以上）。不透明な絵柄なら重なっても見えないが、乗算・不透明度の絵柄では重なった所が濃い線になる（p.86 の天：元 1.5mm → 3.0mm で、元の端に濃い線）
  • 今は、透明効果のあるページは「元の絵柄の端〜断ち代の外端」だけを描く。切り抜きは区間の中の端の位置を 0.5mm ごとにたどった折れ線（端が波打っていても斜めでも合う）。近くの最小値をとるので、ずれるときは隙間ではなくわずかな重なりの側
  • 透明効果のないページはこれまでどおり軸から描く（少し重ねる）。ぴったり接すると、画面のアンチエイリアスで継ぎ目に白い髪の毛のような筋が出る（印刷では出ないが、拡大プレビューで「白い筋」と誤解される）。重なっても見えないので重ねた方がよい
  • 透明効果の判定（usesTransparency）：ExtGState の描画モードが Normal 以外・不透明度 1 未満・ソフトマスク、画像のソフトマスク。Form の中まで見る。ページの /Group は見ない（InDesign の書き出しでは透明効果が無くても付く。00.pdf の p.18 もそう）
  • fillEdges(..., {exact:true|false}) で強制できる。結果の exactPages に「ぴったり描いたページ」が入る

端の位置を細かく測る

  • 判定の 200dpi 画像では 1画素 = 0.127mm。端の画素の塗られ具合（アンチエイリアスの濃さ ÷ 1つ内側の画素の濃さ）で 1画素より細かく出すが、それでも ±0.03mm ほどずれる（poppler は 4×4 の間引きでアンチエイリアスする、大きな四角はアンチエイリアスしない、画像の端は「画素の中心が入れば塗る」など、描き方で変わる）
  • そこで不足の辺だけ、辺の帯（仕上がり線の 1mm 内側〜断ち代の外端）を 1200dpi で描き直して端を測る（refineEdges）。画面は pdf.js の transform で帯だけ描く。帯の長い方が 16000px を超えるときは解像度を下げる。失敗したら 200dpi の値のまま
  • 判定（足りている／足りない・区間・不足量）は 200dpi のまま変えない。測り直すのは補正の切り抜き位置と軸だけ
  • 塗られ具合の中間がほとんど無い辺（画像の端など）は、塗り切られた画素の端が「その画素の中ほど〜次の画素の中ほど」のどこかにあるので、内側の 0.5 画素をとる（隙間を作らない側）

斜めの不足（2026-10-07 p.18・p.19）

  • 写真が少し傾いて置かれていると、断ち代が辺に沿って少しずつ減る（p.18 の天：左 2.0mm → 右 0.05mm）。判定では 0.5mm の段差ごとに区間が分かれる（4か所）
  • 以前は区間ごとに水平な軸で折り返していたので、区間の中で端との差が最大 0.5mm 以上あり、段差状に補われ、重なりも大きかった
  • 今は端の並びに直線を当てはめて、傾いた軸で折り返す。辺に垂直な向きに折り返す（y' = (1+k)·c(x) − k·y、c(x) が傾いた軸）ので、軸の上は動かず継ぎ目がずれない。傾きが小さい（p.18 で 0.9°）ので絵柄の歪みは見えない
  • 接している「足りない」区間がまとめて1本の直線に乗るなら（ずれ 0.15mm 以内）同じ軸にして1つの多角形で描く。別々に描くと、接している境目の1画素が両方に塗られて濃くなる。段差のある区間（halftone_steps.pdf p.2）は別々の軸のまま

角

  • 角はどの部分も1回だけ描く。両方の辺を補うときは、角を「左右側の続き（左右の元の端より外 × 仕上がり線〜天地の元の端）」「天地側の続き」「外側の角（縦横とも折り返す＝点対称）」に分け、それぞれ片方の辺の区間だけが描く。両方の元の端の内側は元の絵柄のまま
  • 片方の辺だけを補う角は、その区間を角まで延ばす（斜めの端・傾いた軸もそのまま延長）
  • 両方を補う角の中は、水平・垂直な軸で折り返す（角での軸の値を使う）
  • 描き方：ページ自身の内容を Form XObject として複製し、変形して断ち代の範囲だけに切り抜いて重ねる。画像は元のオブジェクトを参照するだけなので、再圧縮・ラスタライズ・色変換なし（CMYKのまま）
  • そのため補正したページの内容ストリームぶんファイルが増える（p.15 で約800KB）。増分更新では避けられない
  • 補ったら、補正後のPDFをもう一度判定して確かめる

5. 保存（ノド白と同じ増分更新）

  • 元のバイト列は1バイトも変えず、末尾に追記するだけ。理由：データを壊すリスクを避けたい（中田さん）。ライブラリでの全体書き直し（pdf-lib）は最初に試したが、やめた

7. 画面（UI）の方針

  • KENPAN の他ツールと同じ作り（トンボ計測・ISBN検版の3カラム）。上部ツールバーは下版差分チェッカーと同じ並び：表示（補正前／補正後／スワイプ／並べて）｜ページ（« ‹ n/N › »）｜詳細設定
  • 色：アクセントは桔梗色（#5457c9 / ダーク #8d90f2）。他ツールと被らない色。アンバー／琥珀系は使用禁止（CSS変数名は他ツールに合わせて --amber だが中身は青紫）。スワイプの仕切り線も桔梗色（差分チェッカーはアンバーだったので合わせない）
  • 基本操作はシンプルに、細かい設定は詳細設定に隠す
  • ズームはホイールだけ（修飾キー不要）。カーソル位置を中心に拡大
  • 拡大しても左・上へ戻れること。中央寄せを justify-content:center でやると、はみ出した左・上がスクロール範囲から外れる。margin:auto で中央寄せする（他ツールでも起きた罠）
  • 並べて表示は2ウインドウ（左右それぞれスクロール、位置と倍率は連動）
  • 進め方「まとめて補う／1ページずつ確認」はプルダウンではなくボタン（気づかれないため）
  • 操作ボタンは「このページ」のカードの下に集める（2026-10-07 中田さん）。以前は「残りをまとめて補う」が右上、「このページを補う／次へ」が真ん中、「補正をすべて取り消す」が下の「全体」と散らばっていて、どこを見ればよいか分からなかった。「全体」はスクロールしないと見えず、誰も気づかない
  • 1ページずつのとき：主ボタン（このページを補う／次へ）→ その下に「残り ○ページ（○辺）をまとめて補う」（一段控えめ）→ 破線の下に「補正をすべて取り消す」（文字だけ・右寄せ。押し間違えないよう主ボタンから離す。「戻す」でやり直せるので確認ダイアログは出さない）
  • まとめて補うとき：上の「断ち代を補う」ボタンはそのまま。補正後は「このページ」の下に「補正をすべて取り消す」
  • 「確認 ○/○ ページ（補正・見送り・未確認）」は、上部に固定の「不足 ○ページ」の下に出す。すべて確認したら、ヘッダーの「補正済みPDFを保存」を3回だけ光らせる
  • 下の「全体」は細かい内訳（追記量・レイヤー・処理できなかったページ）だけ。見られなくても困らない内容にする

  • ヘッダーの「リセット」は他ツールに合わせて名前を変えない（PDFを閉じて最初に戻す）

  • 重ね表示（仕上がり線・不足箇所）は目のアイコン・色見本・「表示中／非表示」で意味が分かるように

  • チェック中・補正中は、プレビューの上に進み具合を出す
  • フィードバックは他ツールと同じ GAS。tool は tachi_check

8. 5月の塗り足し漏れ検出（dtp-preflight の BLEED_GAP）との対応

  • 5月：内側1.5mm・外側1.5mmの2点だけを見る（72dpi）。内側 gray≤240（明るい画像も拾うよう緩めた）、外側 gray≥248 を紙とみなす。5mm未満は捨て、25mm以内は1件にまとめる。ノド側は隣ページと照合して重複を抑える
  • 断ち代チェック：外へ連続して測るので「何mmあるか」まで出る。外側は0%だけを紙とみなす
  • toBleedGaps() で同じ形の gaps を出せる。shortage_mm は実測の不足量（5月は辺の断ち代全体を入れていた）
  • 方針の違いに注意：5月は「明るい画像も取りこぼさない」、断ち代チェックは「明るい短い区間は写真の一部」。チェックシステム（お客様に戻す側）を復活させるときは、どちらに合わせるかを決める

10. 既知の制約・未対応

  • 回転指定のあるページは回転前の向きで判定する（表示で注意を出す）
  • TrimBox の無いページは判定しない。BleedBox が無いときは既定3mm
  • 直接埋め込みページ（参照でないページ）、LZW・ASCII85 の内容ストリームは補正できない（警告を出してスキップ）
  • pdf.js は cdnjs から読み込む（和文表示の CMap も）。ネットに出られない環境では動かない
  • 写真の明るい部分で本当に数mm足りないケースは、「写真の一部とみなす」で見逃す可能性がある（方針として誤検知を減らす側に倒した）
  • 透明効果のあるページでも、元の絵柄とぴったり接する境目の1画素（RIP の解像度で 0.01mm 前後）は両方に塗られる（「画素に少しでもかかれば塗る」規則のため。避けられない。目では見えない）
  • 透明効果のあるページを拡大プレビューすると、継ぎ目にアンチエイリアスの白い筋が見えることがある（p.18 の写真など）。アンチエイリアスなしで描くと隙間は無い（印刷では出ない）
  • 端が曲線の絵柄は、端は折れ線でたどるが、軸は直線を当てはめる（3% 点まで内側へ寄せる）。曲がりが大きいと、軸から遠い所は少し離れた絵柄を折り返す
  • 画面の 1200dpi の測り直し（pdf.js）は、この環境では動かして確かめられていない（node の pdf.js＋Skia が透明効果のページで落ちるため）。テストは poppler で同じ流れを通している。ブラウザで p.86・p.18 を補って確かめること

11. 踏んだ罠

  • HTMLだけ配って edge-core.js を置き忘れ → 「undefined is not an object (evaluating 'E.mm2pt')」。部品はビルドで埋め込む
  • .notice{display:flex} が hidden 属性に勝って、空の帯が出た → [hidden]{display:none!important}
  • justify-content:center で拡大時に左へ戻れない（7章）
  • ハイライトの誤検知：4%基準だと5%前後の写真が白扱いになる
  • 補正の境目の白い筋：区間の端を2px重ねて解決
  • pikepdf のオブジェクトを id() で比べても一致しない（6章の Python の件）
  • 反転コピーが元の塗り足しに重なっていた（2026-10-07 p.86）。テストの絵柄が不透明だったので、重なっても見えず気づけなかった。透明効果（乗算・不透明度）のサンプル transparency.pdf を足して、重なりで濃くならないことを確かめるようにした。補正のテストは不透明な絵柄だけでは足りない
  • 濃くなったかどうかをアンチエイリアスありの画像で測ると、継ぎ目の混ざり（白っぽい・濃い筋）と本当の重なりを見分けられない。アンチエイリアスなしで、太さで判断する
  • 斜めの区間を別々の多角形で接して描くと、境目の1画素の列が二重に塗られる → 同じ軸の区間は1つの多角形にまとめた
  • InDesign のPDFはページに /Group（透明グループ）が付いているので、それで透明効果の有無を判断すると全部「あり」になる
